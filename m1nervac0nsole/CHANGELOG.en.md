# Changelog

English

This document records the changes in this edition. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Authorization boundary and platform guards

- Recorded addresses are claims, not DNS answers: a hostname include no longer covers an address the task itself recorded. `netpolicy.AuthorizeRecorded` requires every recorded or vhost-mapped address to be authorized on its own, the gateway re-judges mapped hosts on every request instead of skipping pooled connections, and agent probes fall back to DNS when no recorded address qualifies. `flagPending` counts a name covered only when every recorded address is authorized, and `record_type` is normalized once at insert.
- Agent-spawned tasks write pending scope rules; only the operator's task-creation path auto-authorizes the goal boundary.
- A failed direct-lane policy refresh kills its own process and namespace only. The task's shared execution context is no longer cancelled, so one refresh failure can no longer land every in-flight intent as blocked.
- Scheme-less LLM profile endpoints (`host:port`) parse with the implicit `http://` the agent layer already uses, so a valid profile no longer breaks every spawn while the VPN is up; a genuinely malformed endpoint still fails closed naming the profile.
- `port_scan` re-reads policy during a run and stops when the rules change, refuses while an operator exit is configured, and stores no ports or liveness over 1000 open replies, returning a middlebox note instead. `kill_work` reaches the main agent on upgraded databases via a one-shot binding backfill, and main-agent stops carry the operator cause.
- Finding pins are bounded: artifact manifests open through `os.Root` with no symlink following and a 1 MiB cap, and pinned flows authorize their host and clamp the window to the intent's creation time.
- Evidence fidelity: the recorder stores the headers the gateway actually forwarded, and a refused CONNECT carries the gateway's reason body, so the model can tell a scope block from a credential fault.
- Session INPUT chains drop any packet whose source is not the session's own address, so a raw-socket session cannot forge resolver or gateway traffic; unchanged lane rulesets skip `iptables-restore`.
- Custom HTTP tool calls disable keep-alives per call, the gateway's speed-profile read leaves the cache lock with a deadline, and conversation sessions register revocation once.
- Toolbox installs publish again: the direct-lane client wrapper delegates `Publish` and asserts `execbox.Publisher`, so a wrapped client no longer reports the boundary as unable to publish.
- `tcp_probe` tries every authorized address before calling a host dark and reports the address that produced the outcome; `port_scan` writes the hostname's liveness once, after every address was judged (live if any replied, dark only if all were silent), and stores a dense host's open ports in one bulk UPDATE instead of one per port.
- Guest supervision: the recorder-CA wait yields to SIGTERM and watched-process exits so the kill switches stay armed, and the supervisor tests no longer depend on the host's state directory.

### Local model removal and documentation

- Remove the shared local open-weight model integration: the `./lab primary` command, its shared local-model service wiring and the local-model reasoning verifier (`deployment/verify_reasoning.py`) are gone, and the provenance record no longer carries model-artifact, primary-model or inference-runtime sections. Model access is provider-configured only.
- Rework the published documentation: state the ARTEX lineage and the RSI-loop extension up front, remove the interface-theme descriptions and the refactor-verification blurb, and document the deviations from upstream ARTEX (RSI memory loop, network boundary, subprocess isolation, evidence pinning, browser roles, research environment) with an ingress/egress flow diagram.

### Scoped direct lane and gateway identity

- Retire the separate masking-egress package/process, subcommand and environment settings. Recorded HTTP uses recorder → gateway with Chrome uTLS and selective tool-default UA masking: Stealth uses navigation headers; Careful/Standard/Unbound use UA masking. Enrichment now uses recorded gateway navigation sessions.
- Treat profiles as guidance, with no enforced request-rate or thread ceilings; default tool-run concurrency is 16 global and 16 per target.
- Wrap the installed execbox client for all testing subprocesses, including SDK/Bash, scripts and manifests. Scoped direct access requires live `tun0` and no operator global proxy; research/install remain relay-only. Interactive HTTP retains recorder env. Standard/Unbound `RateRPS` bulk-HTTP manifests omit proxy env and argv only after an available lane snapshot, and refuse execution if it disappears. Raw tools can use the lane regardless of HTTP proxy env; only direct sessions receive `CAP_NET_RAW` for permitted SYN/UDP scanning.
- Enforce authorized includes, exclusions and protocol/port constraints with root FORWARD rules in both directions, including established flows. Deny infrastructure (loopback, `10.98.0.0/16`, link-local, guest-local addresses, `host.microsandbox.internal` and configured native-provider/profile endpoints), not entire VPN destination ranges. Filter DNS A learning, expire it with TTL and re-evaluate it on policy updates. Direct access is IPv4-only; the session link has no IPv6.
- Poll direct policy every second with a combined one-second policy read/apply deadline: revocation normally takes at most about two seconds plus kernel teardown/scheduling. Failures cancel processes, never keep old grants; supervisor apply failures kill sessions.
- Make the built-in Nmap invocation usable as uid 1000 with the scoped raw capability: declare SYN/connect/UDP scan modes and supply `--privileged -Pn -n`, without root or additional capabilities. Add real Nmap XML-classification and ffuf manifest guest-fixture tests, using only disposable local services.
- Sessions on systemd-resolved hosts resolve again: `/etc/resolv.conf` there is a symlink whose target lives on the namespace's fresh `/run` tmpfs, so it dangled and the session inherited a resolver file that answered nothing (the CI runner exposed it). The child now recreates the target and binds the session resolver onto the resolved path — never onto the symlink itself, whose absolute target would resolve against the supervisor's root and attach the mount outside the session.
- CI installs the direct-lane tools (`nmap`, pinned `ffuf`) the kernel tests drive, and provides the disposable database the ffuf manifest test requires; the `go` job's kernel step passes its DSN through `sudo`.
- Guest image: add the ssh client and `bc` (both engagements hit `command not found` mid-run, and one ssh intent died at exit 127), and expose a `certipy` CLI — NetExec's pinned certipy fork installs as a library with no console script, so the binary the agent called did not exist despite the package being present. The additions live in their own final image layer so the heavy layers stay cacheable.
- Make real ffuf runs parseable under uid isolation: stream matches with `-json -noninteractive` instead of reopening the root-owned stdout pipe as an output file, and mount only the supervisor-validated tool-call workspace so task-generated wordlists and request files are visible. The golden fixture now pins the JSONL contract.
- Stop server crashes on cancelled isolated Bash commands. Executor-backed SDK tasks have a session but no `exec.Cmd`; cancellation, `TaskStop` or session cleanup dereferenced the missing command and could kill the backend. Lane refresh also no longer treats a process that exited during its one-second refresh as a policy failure that cancels the whole worker session.
- Direct traffic is unmasked and not HTTP-recorded: preserve execution artifacts and pinned pcap, and replay safe HTTP through the recorder for inspectable evidence. Script bodies and parameters use stdin, not argv. These entries describe source changes, not a deployment or verification result; earlier entries below remain historical.

### Research access, truthful execution and evidence discipline

- Mount the recorder's public CA into every tool session. The backend pointed `SSL_CERT_FILE`, `CURL_CA_BUNDLE`, `REQUESTS_CA_BUNDLE`, `GIT_SSL_CAINFO` and `NODE_EXTRA_CA_CERTS` (and the research browser) at a path the session's mount namespace did not contain, so every HTTPS client in a session failed certificate verification; a plain-HTTP target never showed it. The supervisor now re-encodes the certificates alone from `execbox serve -ca-cert` and binds them read-only at that same path, never the signing key beside them, and the start records the fingerprint in the session manifest so a rotation is visible.
- Classify WebFetch transport failures by stage (policy, credential, DNS, TLS, gateway) with credentials scrubbed, instead of reporting every refusal as a bare `Forbidden` that reads like an internet outage.
- Carry the session credential as the proxy URL's user **and** password. Python's `urllib` and `urllib3` send `Proxy-Authorization` only when both are set, so every Python HTTPS client in a session failed `CONNECT` with `407` while curl succeeded; the gateway still reads the user part alone.
- Reject empty substring exclusions (`ip!=""`): they compiled to `NOT ILIKE '%%'` and silently returned an empty inventory that agents read as "no assets". The error names the supported query instead.
- Reclaim orphaned session namespaces. Teardown removes a session's state directory even when unlinking its network namespace failed because its processes were still alive, and the startup sweep was driven by that directory alone, so such a namespace survived every later start. The sweep now also reads the named namespaces it owns, which is what the live guest had accumulated (six, dated to the crash window).
- Report admission truthfully. `add_intent` and `set_goals` previously acknowledged a stored node as launched work even when admission failed; a failed admission is now an error result that keeps the saved nodes, and goal API responses carry the admission outcome. Steering and hints no longer read as stops or launches.
- Give the main agent a real stop. It had `steer_work` (a next-boundary correction) but no cancellation, so "stopped the workers" was never confirmed. `kill_work` is now available to it and waits for the worker to return from `Execute`, whose deferred `Session.Close` kills the session's process groups, before reporting a confirmed stop.
- Record the operator action beside `blocked_reason`, so a parked task says what resumes it.
- Append code-owned evidence and research guidance to planner, worker and main-agent prompts, so an edited role body cannot drop it: negative results stay bounded by what was tested, template probes isolate expressions (an undefined function rejects the whole template before any valid expression runs), writeup reproduction requires retrieved source text, and a testing-scope refusal is not an internet outage.

### Review fixes

- Let a fresh task reach its own target. The host or IP in the task text is now authorized with a boundary (its /24 or /64, or `*.<root domain>`), and discovered hosts outside it become pending network rules with an operator notification instead of silently blocking the task.
- Relay services that speak first. The recorder waited for the client's first three bytes, so an FTP, SMTP or MySQL banner never arrived; it now relays raw bytes after 2 s of client silence. Raw tunnels are authorized by the gateway dial; their bytes are not recorded.
- Keep guest shutdown and dependency checks responsive while waiting for the recorder CA to appear.
- New `port_scan` worker tool: a TCP connect scan from the backend over a port list, range or `top`, authorized per destination. A hostname is resolved once (task-recorded addresses first, for virtual hosts behind load balancers and reverse proxies), the answer set is authorized, and only those addresses are dialled. `run_tool nmap` now says when the sandbox, rather than the target, explains an empty result, and `tcp_probe` uses the same resolution and no longer marks a host unreachable when the port refuses.
- Stop port scans from reporting the platform as the target. The execbox rules admitted the gateway's port to any address and DNAT'd it to the recorder, so `nmap` inside a session saw `<target>:8788` open (the recorder's own "this is a proxy server" reply) and every other port closed. Admissions now name the session's root address, and refusals are `icmp-admin-prohibited`, so a scanner reads `filtered`.
- Heal the live-transcript stream. A browser whose session predates the HttpOnly stream cookie, or lost it, got a `401` on every `EventSource`, which never retries, so the session list showed "Reconnecting" for good. Any bearer-authenticated API call now re-issues the cookie.
- Fit the Browser tab's live surface to the window, matching the Sessions tab's height, instead of a fixed 16:10 box that ran past the fold.
- Serve `/tmp` in the deployed guest. `run_tool`, `toolbox_install` and the stdio MCP bridge ask for the working directory `/tmp`, which the supervisor's roots (`tasks`, `sessions`) refused, so all three failed. A requested `/tmp` now means the session's private tmpfs; the host's `/tmp` is never bound. Install scripts also receive the install session's proxy env, without which they could not download.
- Let Chromium authenticate to the gateway. Chromium ignores credentials in `--proxy-server`, so the testing browser could not load a page. It is launched with the bare gateway address; the gateway answers a request with no `Proxy-Authorization` with `407` + `Proxy-Authenticate` (an unknown or revoked credential keeps the `403`), and the driver answers CDP `Fetch.authRequired` with the browser's own session, issued at launch and revoked on close or eviction. The browser's stdout is drained, and a launch no longer holds the registry lock.
- Revoke gateway sessions. A credential now dies with the context that owns it (task run, pause, chat turn, MCP discovery); before, only the research proxy revoked, and the 4096-session cap refused every tool spawn until a restart.
- Run custom `script` tools inside the execution boundary. They ran as root in the backend with its environment; they now run in the run's session with only the proxy env and `TOOL_*`, and are refused without a session.
- Ask before an agent rewrites the platform. `update_skill_file`, `create_custom_tool` and `update_custom_tool` are approval-required, and a tool invoked through `ExecuteExtraTool` passes the pre-tool gate under its own name instead of the wrapper's.
- Apply the network policy to backend dials. `tcp_probe` and HTTP asset enrichment ask the same authorizer as the gateway before dialling and refuse when it denies or is absent.
- Make authorization reachable from the console. The task's scope-rule card shows each rule's state with Approve / Revoke; `GET /api/tasks/{id}/scope/rules` carries `authorized`, `protocol` and `ports`; scope-rule writes are audited; editing a rule's effect or pattern drops its approval; an `exclude` rule binds without approval. The redundant `netpolicy` verdict cache is gone.
- Protect the traffic store from its own host names. A captured host named `_index`, `_blobs` or `_ca` made delete/archive remove the store's index or CA; such a host is now stored under a prefixed directory and staging refuses anything that is not a host directory. `DeleteHost` escapes `LIKE` wildcards.
- Record streamed and refused exchanges. SSE, bodies of 5 MiB or more and WebSocket flows left no row; each now leaves one metadata row marked `X-M1nervac0nsole-Capture: body not captured: streamed`. A refused `CONNECT` is recorded with its stage like a refused plain-HTTP request.
- Read spilled finding evidence back. Evidence over 8 KiB was written to disk and never read: the finding view, exports, the task report and archives now carry it, and the evidence GC reaps the files of deleted findings.
- Keep a paused or blocked task alive. A paused task no longer times out, the coordinator uses the deadline credited on resume, and `needs_operator` is not overwritten with `timeout`. Terminal intent writes retry a transient database error, and the goal-met write cannot overwrite a terminal status that already won.
- Keep an operator's knowledge entry. An agent write with the same title is refused instead of replacing the adopted body.
- Rebuild when any package changed. `./lab start` detected staleness from a hand list that omitted `execbox`, `gateway`, `netpolicy`, `traffic`, `browser` and others; it now walks the module. `install.sh` and `update.sh` call `build.sh`; the application image no longer installs a Chromium the driver cannot find; `reset-password.sh` parses `.env` instead of sourcing it.
- `execbox probe` runs in its own state directories, so it no longer tears down a serving supervisor's sessions. CI runs the kernel isolation tests as root and fails when they skip.
- Console: Logs "Load older" sends the session token; the interception scope cannot be saved before it loaded; the skills editor confirms before discarding edits; a webhook URL can be changed (its saved headers are dropped with the old address); findings are polled only while the task runs; findings CSV cells that a spreadsheet would read as formulas are neutralised; severity ordering ignores case.

### Open-issue closure

- One advisory lock for the database suites. Seven copies took `pg_advisory_lock` through the pool and never released it, because `os.Exit(m.Run())` skips deferred cleanup; a second suite could then run unlocked. `internal/testlock` holds the single key on one pinned connection for the whole run and releases it before exit. A reachable database that rejects the lock now fails the suite instead of running it unlocked.
- Build the configured guest image from this repository. `./lab image-build` builds `deployment/sandbox.yaml`'s tag as `<tag>-candidate` from `deployment/Dockerfile`, checks every entry in `deployment/image-capabilities.txt` with `command -v` inside it, and stops without touching the tag, the sandbox or `/state`. `--replace` keeps the previous image as `<tag>-prev-<id12>`. A rebuild is not bit-identical to the historical image, and the command says so. The declared `PWNDBG_COMMIT` and `EXPLOITDB_COMMIT` pins are now actually checked out.
- Delete and archive traffic by task, not by host. A task operation selected rows by host and renamed whole per-host trees, so deleting one engagement removed another's exchanges on a shared host. Selection is now `task_id = ?`, the journal carries the exact exchange IDs (version 2) so a crash replay cannot widen to a host, and compaction deletes only the IDs that were exported. Rows recorded before attribution keep a null task id and are never claimed by a task; the legacy per-host tree is untouched. Explicit host and all-task deletion is unchanged.
- Keep the evidence of every spawned process. `RunOnce` never signalled stdin EOF and returned 255 instead of the child's code; output was lost on a transport error. It now sends EOF, returns the accumulated output with the error, and reports the bytes the child's pipe accepted. Each spawned process writes a per-call directory under the run workspace with submitted stdin, split stdout and stderr (one terminal stream for a PTY), timestamps, exit code and a SHA-256 per stream, and the tool result carries the relative path and the hashes. The environment is never recorded.
- Intercept every browser target before it runs. A popup was recorded after it resumed, an `about:blank` popup was never named, and iframes, workers and shared workers were resumed with no interception. A popup is now recorded before it resumes and named only by an allowed document request; child targets get auto-attach and request interception on their own session before they run; a target that cannot be intercepted is closed rather than resumed, and one Chromium refuses to intercept is released with the gateway as the enforcing layer.

### Trace completeness

- Close stdin without ending the session. A tool that read stdin to EOF never finished: `CloseStdin` closed the whole session and the bridge returned 255. The protocol gains a `stdin_eof` frame that closes only the child's stdin, a PTY session refuses it explicitly, `frameClose` keeps its kill semantics, and the bridge drains both streams and returns the child's real exit code. Proven in the guest for exit 0, 1 and 23.
- Spool streamed bodies instead of dropping them. SSE and bodies over the capture cap left a metadata row and no body. A `StreamResponseModifier` hook now spools every streamed body to a content-addressed blob with no per-exchange cap; the only bound is the capture filesystem reserve, and a breach truncates and labels the stored head rather than dropping it. The 256-event cap now bounds only the live view. A WebSocket stores a JSONL transcript of both directions as its body, and a session is labelled partial when a direction ended with a real transport error or no close frame was seen. The proxy's own teardown - a closed-connection error after the other direction ended - decides nothing, and 1005 and 1006 are local reports of a torn-down connection, never an agreement between the peers.
- Keep a partial enrichment probe. A page over 256 KiB, or one read only partly, was not stored at all, so the asset had no evidence the probe happened. The first 256 KiB is now stored with the declared full length and a partial marker in the stored head, mirroring the traffic contract; a complete probe is unchanged.
- Persist the extension capture queue. Captures queued in memory were lost on a browser restart. The queue now lives in `chrome.storage.local`, capped, with sent ids recorded so a flush after a restart cannot resend.
- Rotate the append-only streams. `native-sse.ndjson` and `host-events.jsonl` grew without limit and were rewritten whole on export. Both now rotate into immutable segments that survive a restart, and every segment is exported.
- Make deletion an operator command. `./lab prune <export-id>` deletes only what a verified export contains: it re-checks every hash, honours a `prunable` allow-list, never touches an active stream, and supports `--dry-run`. A failed export removes its directory. There is no automatic pruning.
- Export the two logs. `egress.log` and the PostgreSQL log travel with an export; the egress CA directory never does.
- Show what an install published. A manifest row now reports the published artifact's path, size, install time and SHA-256, read from the persistent toolbox bin and cached by path, size and modification time. No schema change.
- Attach a popup before it runs. A new target was never attached, so it received no gateway credential and could not load. Every auto-attached target now gets the page's interception on its own session, is refused when the scope rejects its destination, and is reported in the tool result; non-page targets are released immediately so Chrome never waits on a debugger.
- Clamp a declared thread count. The concurrency cap counted scans, not threads inside one scan, so a manifest declaring 50 threads ran 50 under a cap of 3. The declared thread parameter is clamped to the per-target cap before the argv is built and the run record says so; `RateRPS` is unchanged.
- Prove the keylog and the four capture paths. `deployment/verify_completeness.py` runs its own gateway and recorder on a temporary store, mints its own credential and grants only its fixture ports, then pushes plain HTTP, SSE, a 6 MiB body and a duplex WebSocket through and compares collected, retained, exported and consumed bytes per shape after an export and re-import. A listener outside the granted ports must be refused at the policy stage and never dialled. Its keylog fixture proves `tshark` decrypts the gateway's origin flow with the exported keylog and does not without it. It needs no credential and writes no policy row.
- Make the capture verifier run inside a real session. `verify_capture.py` built a bare proxy URL, which the gateway refuses. It now drives `POST /api/tools/custom/test`, so the server mints and revokes the session: no credential is borrowed or staged, and by default it proves the gateway refuses a research session's loopback request and records that refusal with the policy stage.
- Deliver a script tool's body on stdin. The body and its parameters travelled in argv, so they appeared in the recorded host command log and a large script failed to spawn. They now go on stdin to a fixed bootstrap, the executed script is written under the run's workspace and named in the tool result, and an oversized body or `TOOL_*` value is refused with a named error instead of a spawn failure.
- Attribute every captured exchange to the run that made it. Each row carries the task id of the `netpolicy` session the gateway authorized the request with; the traffic API filters by `task_id`, and archives keep it. An exchange recorded with no session keeps a null id.
- Delete the duplicate exchange query. `traffic.Traffic.Search` was a third copy of the paged query, with no callers.

### Network boundary

- Route every recorded request through one origin transport. The recorder no longer dials targets itself: a `gateway` hook answers policy before any name is resolved, checks and pins every resolved address, applies the operator's global proxy as the exit (it no longer replaces the gateway), and completes the origin TLS handshake with the Chrome uTLS profile under strict verification. A recorder that cannot build the hook, or cannot start, now fails startup instead of logging a warning and running without one.
- Require a backend-issued session for every recorded request. `netpolicy` sessions are minted from server-side state (task, conversation, purpose, policy revision) and carried to the gateway as a proxy credential; `Manager.IssueSession` / `RevokeSession` own the registry, an unknown or absent credential is refused at the policy stage, and there is no anonymous session and no default one to fall back to.
- Carry the session credential into every tool-facing proxy. `netpolicy.ProxyURL` is the one place a tool-facing proxy URL is built: the gateway address with the session credential as its user name, and nothing at all when the run has no session or no proxy is configured, so a tool is never handed a bare address the gateway would refuse. Worker/chat/planner/main-agent Bash env and WebFetch, Chromium's `--proxy-server`, the custom `http` tool's transport and `run_tool`'s child env all take the session of the run they belong to; a run with no session gets no proxy rather than an unauthenticated one. The credential never reaches a log line, an error string or an API response: `Session.String` omits it, the manifest preview renders no proxy, and `netpolicy.ProxyURL` leaves an operator proxy's own credentials and a socks5 user part untouched.
- Add the operator policy API: `GET /api/tasks/{id}/policy` (current revision plus every rule, authorized or not), `POST /api/tasks/{id}/policy/rules`, `POST .../rules/{rid}/authorize`, `POST .../rules/{rid}/revoke`, and `GET`/`POST`/`DELETE /api/tasks/{id}/policy/cert-exceptions`. A rule is a grant only after it is approved, a rule the destination contract cannot express is refused where it is written, and every change writes its audit row and moves `tasks.policy_revision` in the same transaction.
- Record a failed attempt honestly. A request the gateway refused or could not forward is stored as that attempt with the stage that decided (policy, dns, dial, tls, transport), not as a target answer, and it no longer marks the host as unreachable. The unrecorded passthrough path is gone: there is no direct dial behind the recorder.
- Stop inventing a proxy for manifest tools. `{{ proxy }}` / `{{ proxyhost }}` render the run's own proxy URL, credential included, and render nothing when the run has no session or no proxy is configured, instead of the hard-coded `http://127.0.0.1:8888`. The process-wide `manifest.SetProxy` is gone: a manifest run takes the proxy from its own run context, so two runs cannot be handed each other's address, and the Toolbox preview renders no proxy at all because a credential must never reach an API response.
- Run every tool process unprivileged, in its own namespaces. `execbox/` adds one narrow privileged supervisor: a session gets a network namespace whose only reachable address is the gateway plus a resolver relay, a mount namespace with the task workspace and the read-only runtime paths, a cgroup v2 subtree, and `setpriv` to uid 1000 with no capabilities; the root namespace admits that session's veth to the gateway port and rejects the rest, and the namespace, rules and cgroup are removed on teardown, cancellation and crash. A host without the capability refuses to start a tool process instead of running it unisolated, and the startup line names the capability that is missing.
- One testing browser, one research browser. The Playwright MCP row, its one-shot migration, the visibility rows that pointed at it, the `browser_driver` setting and its Settings section are gone: `browser_*` is the native Chromium driver, bound to the agents that execute work, and the research browser is Obscura through the gateway. An upgraded install loses the seeded row once; a row created again by hand is kept.
- Stop authenticating `/api` with a cookie. The JWT no longer travels in a browser-readable cookie - the UI keeps a non-secret marker for the route guard, and the only cookie the backend reads is the HttpOnly stream cookie on the read-only SSE GETs. Every other request must carry the token explicitly, so a stale or planted cookie cannot authenticate a mutation; `POST /api/auth/logout` clears the stream cookie.

### Toolbox

- Merge Tools into one **Toolbox** page (`/system/toolbox`; `/system/tools` and its nav entry are gone). The Catalog tab shows manifest templates and custom tools together, the Agent tools tab keeps the system-tool bindings and descriptions, and the Curator tab chats with the new Tool Curator.
- Make templates editable at run time. Edits, new templates and the built-in overrides are stored in the new `tool_manifests` table (a row with a built-in's id overrides it, deleting the row restores it) and take effect on the next run without a rebuild: `POST /api/tool-manifests` (validated by `manifest.Check`, 400 with the message), `DELETE /api/tool-manifests/{id}`. A template may carry an `[install]` script (`script`, `timeout_seconds`, default 600, cap 1800); `POST /api/tool-manifests/{id}/install` runs only that stored, checked script under its timeout.
- Make an install persist. `toolbox_install` and the Toolbox Install button run the script in an install-purpose session that may reach the public web and nothing else (no engagement target, no private, loopback or metadata address), stage under `$PREFIX`, and have the privileged supervisor publish the staged binary into `/state/m1nervac0nsole/toolbox/bin` - a temp name in the same directory and a rename, owner root, mode 0755 - which every session sees read-only on `PATH`. Because it is under `/state`, a tool installed once is available to later sessions and later boots. A failed or unverified install publishes nothing, and the provenance records the published path, digest and size.
- Add the **Tool Curator** agent (`toolcurator`): it reads the toolbox and, from a script, repo URL, docs or `--help` output you give it, proposes a template (`toolbox_propose_template`) or a custom tool (`toolbox_propose_tool`). Both proposals wait on an approval card, the tools are bound to this agent alone, and a proposed custom tool is bound to no agent until you bind it.
- Let the Tool Curator ingest a tool. Its prompt now walks it through cloning the repository into its working directory, reading the docs, running `--version` / `--help` and each subcommand's help, and sampling the real output against a throwaway 127.0.0.1 fixture before it drafts `[emit]`; it installs a missing binary only when asked, and its report separates what it ran from what it inferred. The Curator tab gains an **Ingest tool** dialog (tool, repository, notes, install-if-missing) that sends that request into the conversation. An install that already seeded the `toolcurator` prompt keeps the old text until the prompt is reset in the Agents page.

- Attribute a curator-triggered install to the call that caused it. An install capture was always recorded as an operator action, so an install the Tool Curator started carried no `tool_use_id` and could not be traced back to its call; it now carries that call, and only an install started from the Toolbox is recorded as the operator's.

### Guest image toolbox

### Engagement integrity

- Give hints a lifecycle. `add_hint` / `add_task_hint` accept `supersedes: [ids]`, which marks those hints `consumed`; the planner's graph overview now lists only `active` hints, so a superseded instruction stops arriving every round. `POST /api/tasks/{id}/hints/{hid}/state` closes one by hand, and task wrap-up consumes whatever is left.
- Let the planner retract non-running work. `kill_work` previously errored unless the intent had a live worker; it now falls through to the operator cancel path (soft delete, recorded reason) for open and paused intents, and requires a `reason`, which is recorded on the running path too.
- Ask the planner to reconcile instead of only adding. The hint trigger no longer says "if no intent covers it yet"; it now instructs the planner to treat a prohibitive hint as a constraint and `kill_work` / `steer_work` the intents that contradict it.
- Refuse to auto-complete a task that still has paused intents, and push a churn trigger when three intents on one asset are exhausted so the planner changes technique instead of re-issuing a variant.
- Report coverage explicitly: the generated report has a **Coverage** section naming in-scope assets with no recorded exploration activity, so an untouched host reads as untested rather than clean.
- Block archiving a task whose findings still have no bound traffic evidence (`evidence_version = 0`), naming each finding; `{"force": true}` overrides it for findings that are not HTTP traffic.
- Close two scope-check bypasses. A URL carrying userinfo (`https://user:pass@host/`) reported the user as the host in both the guard's extractor and `scope.ParseAsset`, so the excluded host was never judged; and a service whose address was stored in the `domain` column (the shape `UpsertOtherService` writes for an IP literal) never reached `exact_ip`, `fuzzy_ip` or `cidr` asset-block rules. Both now classify the real host. The egress proxy also checks the engagement gate before its reachability probe, so a refused CONNECT no longer dials the target or answers 502 for a closed port.

### Operational memory

- Deliver what agents write. The prompt-block renderer stopped at the first entry that did not fit and rendered whole knowledge bodies into a 2,200-character block, so on a measured task only 12 of 87 worker reflections ever reached a later worker. One packer now skips an entry that does not fit, clips each item, and reports the ids it wrote; the usage ledger records those, so "shown" means shown.
- Make the start-of-task block an index: adopted environment entries in full, then one `K17 [technique] <title>` line per adopted entry the task can see. `recall(id="K17")` returns the full text under the same visibility rule as search.
- Build the per-launch and per-round block from one selector (`db.SelectMemory`) instead of four separate paths: prior attempts by finished intents on the same assets, each shown by its best-matching yielded fact; four reflection slots with tooling lessons and same-asset rows first and agent-written rows ahead of engine rows; and an index of the task's own candidates.
- `reflect` accepts `scope: tooling` for a lesson true of every worker, and `about` + `verdict` (`confirmed|wrong|stale`) to judge an earlier item. A verdict renders next to its target and never hides it; no agent changes an entry's status.
- `recall` builds its query with PostgreSQL's own parser, normalises rank by length, ignores terms that match most entries, and searches every reflection instead of substring-matching the newest 50.
- Record the origin intent of an agent-written knowledge entry (`knowledge_entries.origin_intent_id`).
- Add a review queue. `GET /api/knowledge/review?task_id=` lists a task's candidates ordered by what their origin intent produced, with the redaction count a promotion would make and the nearest adopted entry; the Memory page's Review view promotes through the existing bulk action. Finished tasks with candidates show "N to review" on the tasks list and detail page (`GET /api/knowledge/review/counts`), and the archive dialog says how many unreviewed candidates will be lost.
- `GET /api/memory/preview` takes `intent_id` and renders the launch block that worker got, as of its launch.
- Ask a worker that ran out of budget for one `reflect` before its closing sentence; those runs previously left no lesson.
- Remove the engine's "defence response" reflection, a substring match on 403/429/captcha/waf/blocked that fired on file sizes, hex blobs and the engine's own hook messages and then took prompt slots from reflections workers wrote.
- Stop the scrubber corrupting technique text: `::` scope syntax (`[Convert]::ToBase64String`), OIDs and glued version numbers (`v1.8.0.191`) are no longer read as IP addresses, loopback and unspecified addresses are not target identifiers, and `basic authentication`, attribute-only `Set-Cookie:` lines and word-shaped slash paths survive. The rules fail closed: a slash run that is not made of words, a cookie line with any non-attribute pair and a bare four-part number (indistinguishable from an address) are still redacted. Credentials and routable addresses are redacted as before.
- Scrub and filter RSI lessons at render time the way knowledge is (they skipped both), and truncate them on rune boundaries.

### Browser and live graph

- Make the exploration graph live. The graph tab polled every 20 s, so a finished intent looked running until the next poll. It now subscribes to the activity stream, folds events through a pure reducer (a 2 s activation pulse and a per-node output tail capped at 40 lines), and schedules one debounced refetch per burst; the 20 s poll survives only while the stream is down. Intent state transitions are announced from the single choke point that persists them, so a terminal state repaints at once instead of waiting for an unrelated event. Clicking an intent opens a drawer with its live tail plus pause, resume, cancel and a worker message.
- Give workers a real browser. Chromium and the Playwright MCP already ship in the guest and the manager already routes it through the recording proxy with the MITM CA; the MCP row was seeded disabled. It is now enabled, with a one-shot migration that flips an untouched install and never resurrects a later toggle-off, and a `browser` skill teaches the snapshot-then-act loop and the operator hand-off.
- Judge the browser against the task boundary. Every `mcp__browser__*` call is checked: a navigation's URL before the page loads, and the page each call reports afterwards, so a server-side redirect or a click that navigates cannot land the run off-scope. Out-of-scope hosts, non-http(s) schemes, non-ASCII hosts, non-canonical IPv4 spellings and backslash tricks are refused; a task with no scope checker is refused rather than guessed.
- Let a screenshot reach the operator without entering the conversation. With provider credentials configured an image cannot be redacted the way the question text is, so `ask_operator` no longer refuses it: the file is staged and named by path in the hand-off, and the operator opens it in the task workspace.
- Bind the browser MCP directly instead of through the skill gate. A server named by a visible skill's `mcps:` is deferred until the model loads that skill, and two measured runs showed it never does: the tools were listed in the prompt, never unlocked, never called. The Playwright server is now bound to the agents that execute work; the `browser` skill stays as the how-to.
- Make the shipped browser MCP actually start. It was spawned as `npx @playwright/mcp`, and npx resolves the package over the network while every child inherits the egress proxy, so the handshake hung until the caller's deadline; the image's global `playwright-mcp` binary is used instead. The row also names the image's Chromium (`--executable-path /opt/ms-playwright/current/chrome`, a stable link the image now builds), disables the sandbox because the guest runs as root, and accepts the recorder's certificate (`--ignore-https-errors`, added and removed with the proxy) - without which every `https://` navigation failed with `ERR_CERT_AUTHORITY_INVALID`. One-shot migrations rewrite an untouched seeded row; a row the user edited is left alone.
- The browser is scope-judged on what it is told, not on what it does. `browser_navigate` passes the scope guard because it carries a URL; a click, a form submission or `browser_evaluate` can still reach a host the task excludes. The recorder captures that traffic and the browser skill forbids directing the browser outside the boundary, but the guard does not enforce it. Accepted because the browser is opt-in for an engagement; enforcing it belongs at the proxy, which sees every host before the page does.
- Report why an MCP server failed to start. A stdio server that exits during the handshake reported only `connection closed`, with its stderr discarded; the child's last 4 KiB of stderr now rides in the error and on the MCP page.

### Browser driver

- Harden the native browser driver (Plan C follow-up, `docs/design/browser-hardening-plan.md`). The idle reaper no longer closes a browser whose task still has work running, so a long scan between two browser steps keeps the page it logged in to. `browser_close` exists, and concurrent browsers are capped at four with the least-recently-used idle session evicted. `browser_navigate` returns the snapshot, so a navigation costs one turn instead of two. `browser_snapshot` takes a `ref` to read one subtree and a `max_lines` cap. `browser_log` returns console output and JS exceptions with a cursor, so a page that fails to render says why. Downloads land in `tasks/<id>/downloads` and are named in the next tool result.
- Enforce the boundary on every request, not just on navigation. The driver enables CDP `Fetch` interception and refuses any request whose host the task excludes, before it leaves the browser, so a redirect, an image or an XHR cannot put an excluded host in the recorded traffic; the tool result names what was blocked. The decision is cached per host for a minute, and `data:`/`blob:`/`about:` are allowed because they never reach the network.
- Audit the operator. Input in the live view writes one activity row per burst (`operator mouse on <url>`), debounced to one per two seconds, never carrying the typed text. The stream now names the page it shows (`page {url, title}`) and takes per-viewer `width`/`height`/`quality`, clamped, so a small panel does not stream 1280x800. While an operator holds the live view, the agent's browser tools refuse with "the operator has the page" instead of fighting for the pointer.
- The real-Chromium driver test now runs in CI: the `go` job installs a browser, points `M1NERVAC0NSOLE_CHROMIUM` at it and runs `TestIntegrationRealChromium`, so a launch-flag or pipe regression cannot reach main unobserved.
- The browser surface is a setting, not a SQL edit: System Settings has a **Browser** section whose Driver select offers *Native (built-in)* and *Playwright MCP*, backed by `browser_driver` in `GET`/`PUT /api/settings` (`native`/`mcp`, anything else is a 400). It applies to the next run, like every other tool-assembly toggle.
- The live view no longer leaves the agent pinned to the viewer's geometry: starting a cast records `Page.getLayoutMetrics` and stopping it puts that viewport back, so later agent screenshots and clicks use the size the agent had.
- `browser_click` scrolls the element into view (`DOM.scrollIntoViewIfNeeded`) before reading its box model, so a ref below the fold no longer clicks whatever happens to sit at its old coordinates.
- Give the guest its own browser driver. `browser/` speaks CDP over Chromium's `--remote-debugging-pipe` - no WebSocket, no new dependency - and implements the snapshot/ref contract: `- role "name" [ref=gNeM]`, with value, checked, disabled and required rendered, 2000-line cap, and refs invalidated by a generation that bumps on every top-level navigation (`stale reference, take a new snapshot`). It also carries the dialog policy (accept within 2 seconds of an agent action, otherwise park the dialog for the operator) and crash recovery on the same profile.
- Ten tools - `browser_open`, `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_press`, `browser_select`, `browser_wait`, `browser_screenshot`, `browser_upload` - bound to `auto`, `pentest` and `worker` only, wrapped by the same scope guard as the MCP tools (the navigation argument and the page it landed on), launched against the recording proxy so every request the browser makes is evidence. `browser_driver` selects the surface (`mcp` by default, `native`); when native, the MCP browser row is disabled so a prompt never lists two browsers, and idle sessions close after ten minutes.
- `browser_screenshot` writes the PNG into the task workspace and returns its path; the harness has no image tool result, so the path is what the model and the operator get.
- Let the operator watch and take over the agent's browser. `GET /api/tasks/{id}/browser/stream` streams JPEG frames over SSE (`Page.startScreencast`, every frame acknowledged, a slow viewer drops frames instead of stalling the CDP loop), starting with a `viewport` event and announcing a parked dialog; `POST .../browser/input` forwards mouse, key, wheel and text events, and `POST .../browser/dialog` answers the parked dialog. Input takes the same scope check as a tool call, one operator stream per task holds a token (a second viewer gets 409 until it releases or disconnects), and the task detail page gains a Browser tab with a take-control toggle.

### Scope rules

- Let the operator write rules over the boundary the hunt accumulates. ### MCP server and API tokens

- Give an external harness a credential that cannot do more than read one engagement. `POST /api/tokens` mints a token bound to one task, expiring (1-720 hours), revocable, stored as a sha256 hash and shown exactly once; `GET`/`DELETE /api/tokens` list and revoke. The new **API tokens** page mints and revokes them.

### Drafted plans

- Let an operator draft a plan in plain language. A new `drafter` assistant turns an approach into a proposal - goals, seed intents, hints and scope rules - with two tools of its own (`plan_context`, `propose_plan`), each seeded bound to that agent alone so no worker or planner can call them; it reads the tool catalogue through the shared `list_tools`. Exclusions apply directly because they only narrow the engagement; inclusions need an explicit `allow_include`, because they widen what the guard allows.
- The churn trigger de-duplicates per asset in memory for the life of a task, so after a restart the same asset can be announced once more. Accepted: the trigger is advisory, and a repeated hint costs a planner round rather than a wrong action.
- One pending draft per task: a new proposal supersedes the previous one instead of piling up, and discarding is a status change, never a delete of what an applied draft created.
- Bind the drafting conversation to its task. `plan_context` and `propose_plan` take the task from the thread rather than from the model, and an id that disagrees is refused with the bound task named - a model that guesses would otherwise store a draft against an engagement the operator never asked about, one click away from being applied. - Draft scope rules from a pasted program policy. `propose_scope` takes a summary and a list of rules and runs the same validator, the same draft table and the same apply transaction as `propose_plan`, so a scope-only draft is reviewed and applied exactly like a full plan; an inclusion still needs `allow_include`. ### Stopping the absence loop

### Memory that can be read back

### A proxy that cannot fake reachability
- The masking egress proxy answered `CONNECT` with `200 Connection Established` before it had dialled anything, so a tool saw a successful tunnel and a forged certificate for a host that does not exist, and the real failure arrived inside the tunnel as a 502 that read like the site's answer. CONNECT is now preceded by a TCP probe (3 s timeout) cached per authority (2 min, 4096 entries), and an unreachable target gets a 502 labelled `X-m1nervac0nsole-Egress: dial-failed` with no certificate minted.
- Every proxy-generated failure carries that header, and enrichment drops a response that has it: no service row, no `last_seen` bump, no exchange recorded against the target. A 502 the masker produced can no longer be stored as the target's status code.
- Relay plaintext CONNECT tunnels instead of terminating TLS on them. The recording proxy always CONNECTs to its upstream, even for an `http://` target, so a plaintext request arrived at the masking proxy, was consumed by a TLS handshake, and the client got a bare 502 with nothing captured: every plain-HTTP target was invisible to the traffic record. The proxy now peeks one byte after `200 Connection Established` - `0x16` still opens the TLS path with the browser fingerprint, anything else is relayed verbatim - and the relay keeps the reachability probe, the engagement gate and the request log. Setting a global proxy now says in the UI that it replaces the mask as the recorder's upstream.
- Assets carry `last_unreachable_at`, `open_ports` entries carry provenance (`model` for an `insert_assets` claim, `probe` for an observed connection), and `graph_overview` exposes a `target_liveness` block, so absence is a fact the planner reads instead of prose it infers.
- New `tcp_probe` worker tool: a direct dial that ignores the proxy environment, distinguishes connected / refused / timed-out / DNS failure, and writes the liveness result.
- A successful enrichment probe clears `last_unreachable_at`: a host that answers HTTP is reachable, and only `tcp_probe` used to be able to say so. The clear runs on the probe's own transaction, so it commits with the result that proved it.
- The masking proxy keeps its browser encoding fingerprint upstream but decodes gzip, deflate or brotli when the downstream client did not negotiate that encoding. Curator WebFetch can now read compressed sources instead of receiving binary data with a successful HTTP status; decoding failures are labelled proxy failures. Enrichment advertises the encodings it handles so its raw response capture remains unchanged.
- A regression test pins the recording proxy's CONNECT honesty. It dials upstream before answering because `UpstreamCert` defaults to true, and with the masking proxy probing first, a tunnel to a dead host now fails at CONNECT instead of succeeding against a forged certificate. Nothing asserted that before, so adding `NewUpstreamCertAddon(false)` would have silently restored the artefact.

### Audit fixes

- Stop web search and WebFetch from inheriting the ambient `HTTP_PROXY`/`HTTPS_PROXY`. `web_search_proxy` and `WebFetchProxy` document "empty = direct", but an empty value fell through to `http.DefaultTransport`, so in the deployed guest every search left through the masking egress proxy — which owns the `Accept` header and replaces it with a browser value. Brave Search validates that header and answered `422 Unable to validate request parameter(s)`; DuckDuckGo's scrape endpoint saw the masked identity instead of the client's own. An empty proxy now dials directly (`tool.newFetchClient`), matching the per-profile LLM proxy's rule in `agent/provider.go`. The transport is cloned from `http.DefaultTransport`, so the dial timeout and HTTP/2 support it used to inherit are kept.

- Admit a scan whose declared rate exceeds the engagement ceiling instead of waiting forever. The reservation is clamped to `MaxRequestsPerMinute`, so the shipped `ffuf` (50 rps), `feroxbuster` (50 rps) and `nuclei` (150 rps) defaults start at the cap; fractional rates (`-rate 1.5`) are parsed as a real budget instead of silently disabling the check.
- Key the per-target rate gate and the scan limiter on one normalised host, so `EXAMPLE.com`, `example.com.` and `example.com` share a budget, and two distinct IPv6 literals no longer collapse into one bucket.
- Reject a negative or overflowing chunk size in the egress proxy. `ParseInt` accepts a leading sign, so `-1` reached `make()` and panicked the process — reachable from an untrusted origin's response as well as a client body. Honour `Transfer-Encoding` over `Content-Length` rather than acting on whichever header appears first.
- Restore `127.0.0.1:8787` as the `-addr` default; the placeholder value could not bind, so a flag-less launch failed at startup.
- Extract the candidate assets of a tool call from its decoded JSON values as well as its raw bytes. One escape (`\u0065vil.example`) previously defeated both the scope exclusion list and every intercept deny rule, because the guard inspected the encoded envelope while the tool executed the decoded value. Bare IPv6 literals and mixed-case hostnames are extracted too.
- Give the exclusion side of the task scope a writer: `effect` is persisted by the scope INSERT, accepted by `add_task_scope` and `POST /api/tasks/{id}/scope`, and rejected for kinds the guard cannot evaluate. A `root_domain` exclusion now covers its subtree, and a rule that could never match an asset is refused instead of stored.
- Key the scope dedup index on `effect`. Auto-scope records every discovered host as an include, so the ordinary case — excluding a host the task is already scoped to — hit that row, was dropped by `ON CONFLICT DO NOTHING`, and the API reported success while the guard never fired. Both rows now coexist and the exclusion wins.
- Keep exclusions out of the coverage denominator and the untested backlog, and unify the last duplicated scope-to-asset predicate. An excluded host was counted as in-scope, so the agent was told to test what the guard refuses and coverage could never reach 100%.
- Extract IPv6 CIDRs and compressed literals in the scope scan. `net.ParseIP` rejects `2001:db8::/32`, so an excluded IPv6 range was never enforced, and the candidate normaliser trimmed the colons off `::1` and `fe80::`.
- Fail closed when a safety check cannot read its rules: the asset gate, the scope checker, and the intercept enabled-tool cache now refuse rather than allowing everything. A database blip previously degraded each of them to "allow all".
- Check the `Link` and `SetNodeState` errors before `prove_goal` declares a task complete, so a task cannot close on evidence that was never persisted.
- Return in-flight intents to the frontier on a graceful shutdown. `shutdown` was missing from the pause-cause list, so every restart marked them `blocked` — a state the frontier never selects — and silently discarded the work in progress.
- Read the per-task LLM rotation chain through its mutex-protected snapshot; the unlocked slice read could index out of range and panic the process after a chain edit.
- Match intercept deny rules against the decoded arguments, not only the encoded envelope. `{"command":"\u0072m -rf /"}` decodes to `rm -rf /` and ran while no rule matched; the guard's scope scan had already been fixed, but the rule matcher had not.
- Repair a corrupt worker transcript instead of failing the run. Surfacing the error was right, but the transcript id is deterministic per intent, so every retry hit the same bytes and the intent was parked in a state the frontier never selects — permanently bricked. The partial trailing line is now dropped, and only an unrepairable file is moved aside.
- Validate that a loaded CA can actually sign: it must be a CA, permit `keyCertSign`, and be valid now. A matching key/cert pair that failed any of these loaded cleanly and then produced "unknown authority" at every tool.
- Cap node summaries at 160 runes everywhere they reach an agent, not only in `list_facts`. `graph_overview` embeds recent facts in the planner's current turn on every round, where compaction cannot evict them, so one oversized summary could permanently exceed the context window.
- Bound the `limit`/`size` query parameters of the activity, frontier, conversation and command endpoints. An unbounded value reached SQL `LIMIT` verbatim, so one cookie-authenticated cross-site GET could materialise every row with its metadata.

- Use one scope-to-asset predicate for both the coverage denominator and the agent's asset context. - Translate application-authored errors, notifications, role/tool metadata, editable built-in prompts, and conversation framing. Use English date formatting and native English mention kinds while retaining readers for historical mention syntax.
- Migrate only exact known shipped prompt/tool/trigger defaults. Preserve operator-custom values, tool bindings, limits, historical conversations, and all previous prompt versions.
- Write model approval reasons with `[Model]` while keeping classification and display support for records written with the legacy Chinese prefix.
- Translate authored source comments into English, including embedded SQL, script heredocs, and Markdown code fences. Preserve non-comment code and literal legacy protocol data.
- Translate the prompts that reach the model, which the earlier pass missed: the cold-node compaction prompt, the planner's to-do and change blocks, the worker's traffic and artifact rules, the goal framing, and the judge's input boundary. The compaction prompt being Chinese made every compacted summary come back in Chinese and flow on into planner context and the graph view. Chat mention labels shown in the dropdown are English too.
- Preserve every legacy and third-party match string byte-for-byte, but spell each non-ASCII character as a `\u`/`\x{}`/`U&` escape so no CJK character remains in source: the legacy `[Model]`-era reason prefixes and mention tokens for saved history, the relabel migrations and orchestration constants that match shipped bytes verbatim, ICP scope keywords, log-severity keywords, and the quota markers that classify provider error text (an upstream may answer in Chinese whatever this application's own language is).
- Replace the web-only CJK check with `scripts/check-cjk.py`, which gates every authored source file (Go, Python, TypeScript, JavaScript, JSON, CSS, SQL, TOML) and the built HTML, and rejects any CJK codepoint outright — with no content exceptions, since every retained match byte now lives only as an ASCII escape. The old check read only `web/out` and `web/src`, so a Chinese prompt string that no browser renders but every model reads passed it — which is how the compaction prompt drove the model to answer in Chinese unnoticed.

### Fixed

- Distinguish task report loading failures from empty reports and offer a retry button. Late responses from a previous task cannot replace the current task report.
- Standardize benchmark runner (`scripts/benchmark/run_bench.py`) authentication on valid session `M1NERVAC0NSOLE_TOKEN` or `/api/auth/login` session tokens via `M1NERVAC0NSOLE_PASSWORD`, removing obsolete raw `M1NERVAC0NSOLE_JWT_KEY` minting to match password-hash-derived JWT signing.
- Strengthen trace exporter test coverage in `deployment/test_export_traces.py` to exercise task credential scrubbing across open-weight reasoning, provider summaries, tool arguments, tool results, and text, ensuring corrupt snapshots fail closed and raw snapshots remain byte-for-byte unchanged.

#### Data loss and correctness (audit)

- **Behaviour change.** Archive compaction refuses to delete a host whose exchange count grew after the archive snapshot, and records the refusal as a task-archive warning. Captures taken while a package is compressing are no longer deleted from the hot store, so an archived task may retain traffic until a later cleanup.
- **Behaviour change.** A provider key taken from a saved LLM profile is now only ever sent to that profile's stored `base_url`. Testing a different endpoint requires supplying that endpoint's own key.
- **Behaviour change.** `traffic.json` in an archive package is written as a stream instead of being assembled in memory and marshalled. The structure and meaning are unchanged; field order differs and memory use drops from roughly six times the captured bytes to one exchange.
- **Behaviour change.** The tool-approval gate now denies when its rule set cannot be read — it keeps enforcing the last set that loaded, and refuses rather than allowing if none ever loaded. Previously a database outage silently let every call through.
- Credential re-saves with a blank password keep the stored one instead of overwriting the agent-generated secret with an empty string.
- Workspace uploads stage to a temporary name and rename on success, so a copy that fails partway no longer truncates the file already on disk.
- Failed captures (blocked, aborted, DNS failure) are recorded with status 0 and the transport error instead of being dropped by the browser extension, and are no longer rewritten to HTTP 200 by ingest.
- Exchange ids no longer wrap within one second, so a burst no longer overwrites already-stored captures.
- A task-delete staging journal records the task id, so a process exit between the PostgreSQL and SQLite commits is resolved on restart rather than leaving traffic orphaned.
- Skill-editor file reads are guarded against out-of-order responses, so a slow read can no longer save one file's contents into another.
- JSON request bodies are bounded at 8 MiB, with the skill-file route raised to its documented per-file limit; an unauthenticated oversized body no longer amplifies into gigabytes of heap.
- Exporter redaction covers scheme auth headers, `Cookie`/`Set-Cookie`, camelCase credential keys and URL-encoded task passwords; unparseable records are rejected rather than aborting the run, and `train.jsonl` is replaced atomically so a failed export leaves the previous dataset intact.
- Provider error bodies are bounded and scrubbed of credential shapes before reaching `llm_health.last_error` and `llm_records.error`, both of which are displayed in the UI.
- The worker conclusion read by the planner and `get_worker_output` reads newest-first, so a long tool-heavy run no longer reports that its worker produced no output.

#### Runtime failures found by running an engagement

- **Behaviour change.** The pcap ring is sized from the filesystem it writes to instead of a fixed 32 x 128 MB. On a 4096 MB `/state` quota the fixed ring was 4 GB: a live engagement reached 3.4 GB of capture, the volume hit zero bytes free, and m1nervac0nsole, PostgreSQL and the supervisor all went down with it. The ring now leaves a 1536 MB reserve, keeps the 32-segment value as an upper bound and a 4-segment floor, and the manifest records the ring actually used rather than the one requested.
- The built-in critical-path rule matched a bare `/` as its first alternative, so it denied any command where `rm` stood within 60 characters of an absolute path — an agent's own cookie-jar cleanup was rejected because `curl` later in the same line used `-D /dev/null`. The gap now excludes `;`, `&` and `|` so the path must belong to `rm`'s own simple command, and root matches only as a whole token. Existing databases are rewritten by `migrateCriticalPathRuleV5`, which touches only a row still holding the shipped bytes.
- Captured response bodies no longer end mid-rune. The capture bound is a byte count, so the cut landed inside a 3-byte character and PostgreSQL rejected the entire `llm_records` insert on that byte (SQLSTATE 22021), losing the record. The cut now backs off to a character boundary first.
- Tool output returned to the model is bounded at 8000 characters instead of the 30000 default. A live worker call carried 253 KB of tool results — 76% of a 341 KB request — and the transcript is re-sent every turn, so five oversized messages accounted for 22% of every request. The spill file still keeps the full output and the tool returns a head plus a pointer.

### Added

- **Enforced engagement boundary.** `scope` evaluates an asset against include/exclude rules and the tool guard refuses a call naming an excluded host, so the boundary is a decision rather than a sentence in the prompt. An exclusion always wins over a more specific include; among includes the longest pattern wins; an asset no rule mentions is `unknown`, never `out`, because a pasted scope table is routinely incomplete. `task_scope` gains an `effect` column and a row with `effect='exclude'` is enforced. `scope.Problem` rejects a rule that could never match an asset — a program's out-of-scope section is usually a mix of *where* and *what*, and filing "denial of service by flooding" as a scope rule leaves the engagement looking bounded when it is not. (`scope/`, `guard/scope.go`, `db/task_scope_check.go`)
- **Asset kind derived from the value.** `AddAutoScope` now decides whether a value is an apex, a subdomain, an IP or a CIDR from the value itself, keeping the caller's label as a hint. One host filed as both `domain` and `subdomain` made a boundary that matched neither. (`db/scope_kind.go`)
- **TOML manifest layer for external tools.** 32 manifests declare a tool's parameters, its argv template, how its output splits into records, and which record fields become an asset or a fact. The set is embedded in the binary, so a deployment cannot ship without it. `run_tool` executes a manifest-backed tool and returns parsed assets and facts; `list_tools` exposes the catalog. `GET /api/tool-manifests` serves the same declarations to the UI. Every manifest has a golden case in `manifest/testdata/golden/`, and `TestEveryManifestHasAGoldenCase` fails when a new tool ships without one. (`manifest/`, `server/manifest_tools.go`)
- **Finding evidence spilled to files.** Evidence above 8 KiB is written content-addressed under the evidence directory and referenced from `findings.evidence_path`, so a list query no longer carries megabytes of request bodies it never reads. Content addressing means the same evidence recorded twice writes one file, and the filename doubles as an integrity check. (`evidence/finding_evidence.go`, `findings.evidence_path`)

#### Regressions restored from the upstream base

Four behaviours that this fork had lost relative to its own base commit (`7f8c7cb`), each with the test that guards it:

- **Behaviour change.** `POST /api/skills` and `PUT /api/skills/{name}` emit YAML-quoted frontmatter values and re-parse the written file before answering. A description containing a colon, `#`, flow bracket, quote or comma used to produce unparseable YAML: every field after the metacharacter was dropped, the skill loaded under its directory name with an empty description, and a skill-gated MCP server was skipped without a word. A write that does not round-trip now returns 500 and is rolled back instead of landing silently. (`server/skill_frontmatter_test.go`, `server/shipped_skills_test.go`)
- **Behaviour change.** `GET /api/tasks/{id}` returns the same token and goal aggregates as `GET /api/tasks`. The detail response previously carried zeros, so a task page showed no spend and no goal progress until the separate stats poll resolved. (`server/task_detail_metrics_test.go`)
- **Behaviour change.** The `mcp_status` platform tool reports each MCP server's transport, enabled state, cached tool count and last connect outcome, so an agent can tell a broken server from one it never needed. It seeds on the next start and defaults to the Auto agent, like the other platform tools. (`server/platform_tools.go`)
- **Behaviour change.** Testing a saved LLM profile with the form's `streaming` field omitted now uses the profile's stored stream mode. A non-streaming profile tested from the list view was sent a streaming request and reported "no return text" for a provider that had answered correctly. (`server/llm_test_fallback_test.go`)

### Added

- **`privesc` skill** covering Linux and Windows escalation: enumeration order, sudo/SUID/capability escapes, service and cron misconfiguration, credential discovery, and the four-part proof standard for an escalation finding. Ships two generated indexes — `reference/gtfobins.json` (458 executables by escape class and context) and `reference/lolbas.json` (248 signed Windows binaries by category) — plus the PEASS-ng `linpeas.sh` release artifact, all usable offline at a pinned version. `scripts/build-indexes.py` regenerates the indexes from the upstream trees; provenance and checksums are in `reference/README.md`.

## [0.3.15-ko.1] · 2026-10-12 · First Korean-edition release

The first release of the Korean edition, based on upstream m1nervac0nsole 0.3.15.

### Distribution

- **The Korean-edition Docker image is now published.** Upstream's `autumn27/m1nervac0nsole` image was taken down from Docker Hub, which broke the `docker compose up -d` quick start. Each release tag now pushes a multi-architecture (amd64/arm64) image to `ghcr.io/jiwoochris/m1nervac0nsole`, and `docker-compose.yml` pulls that image.

### Security

- **Blocked remote takeover of the first-run admin account.** An instance without a password accepted `POST /api/auth/init` unauthenticated, so whoever reached the port first could set the admin password and obtain a JWT (privately reported by Dangel). Initialisation now requires the setup token (`setup_token`) printed only on the server console at startup, and wrong attempts are rate-limited. Added `M1NERVAC0NSOLE_SETUP_TOKEN` and `M1NERVAC0NSOLE_ADMIN_PASSWORD` for unattended deployments and a token field on the `/setup` screen.
- **Default bind address is now 127.0.0.1.** The `m1nervac0nsole -addr` default moves from `:8787` to `127.0.0.1:8787`, and `docker-compose.yml` publishes 8787 as `${M1NERVAC0NSOLE_BIND:-127.0.0.1}`. Deployments reached from other machines must pass `-addr :8787` or set `M1NERVAC0NSOLE_BIND=0.0.0.0` in `.env`. Starting without a password on a non-loopback address logs a warning.
- **Changing the password invalidates every existing token.** The JWT signing key is derived from the password hash, so a change through the UI, `reset-password.sh`, or a direct DB edit ends earlier sessions. Users must log in once after upgrading. The change-password response carries a fresh token so the current browser session continues.
- **Replaced wildcard CORS with an allowlist.** Instead of `Access-Control-Allow-Origin: *`, headers are only sent for origins in `M1NERVAC0NSOLE_CORS_ORIGINS` (default: `next dev` at `http://localhost:5173`). Also added server-side minimum password length (8) and audit logs for failed initialisation/login attempts (with client address).
- **Ported the authentication hardening from upstream m1nervac0nsole 0.3.15.** Password-setting reads now fail closed with 503 instead of reporting `initialized:false` (`authStatus`, `authInit`, `authLogin`, change-password). First-time setup is atomic via `INSERT ... ON CONFLICT DO NOTHING` ([`db.InsertSettingIfAbsent`](db/settings.go)), so the primary-key constraint protects the existing value even when the read check is unreliable. Passwords over 72 bytes are rejected with 400 instead of 500, and a database connection-pool cap (32) reduces the path where a `too many clients` error can masquerade as a read failure. Ported to match upstream commit `a951e4a` (0.3.15); only the parts not already covered by PR #20 were added.
