# m1nervac0nsole: UI refactor and rebrand plan

## Direction
Adapt minervacyb.org's actual visual system to an operational console, not its portfolio page geometry. Browser/CSS inspection confirmed black #000, surface #101010, hairlines #303030, off-white #f2f2f2, muted #a8a8a8, blue-gray accent #a9b8c6, Manrope body/headings and DM Mono navigation/metadata. Use open sections and flat, low-radius controls. Retain semantic warning/error/success colors, readable tables and dense operator workflows. No oversized marketing hero, scanlines, glow or decorative terminal animation.

## Ordered implementation slices

1. **User-facing identity.** Centralize the exact display name `m1nervac0nsole` in `web/src/config/app-config.ts`; update metadata, sidebar wordmark, login/setup copy, app icons/favicon, notification and report product copy, current docs and screenshots. Preserve AGPL notices and explicit ARTEX/Norma upstream attribution. Do not bulk-replace historical records or saved user content.
2. **Design foundations.** Implemented the reference colors through existing semantic tokens, local Manrope and DM Mono, clamped near-square radius math and flat shared controls. The subsequent user decision superseded theme migration/light-mode support: appearance is fixed dark; theme, font, preset and layout options, persistence, generators and unused dependencies are removed. Sidebar open/closed state remains functional.
3. **Shell and navigation.** Refine `(main)/layout.tsx`, `main-content.tsx`, sidebar components and sidebar-items.ts. Flat sidebar, restrained wordmark, single hairline header, persistent status/approval access. Proposed groups: Operations (Overview, Tasks, Chat), Evidence (Findings, Assets, Traffic, Tool Runs, LLM Records), Intelligence (Memory, Skills), Configuration (remaining system pages). Keep route URLs and navigation ids stable, and update the command palette from the same nav data. Any new grouping must not remove access to less-used existing screens.
4. **Shared surfaces.** Update Button/Card/Badge/Tabs/Table primitives once; remove unnecessary nesting and hardcoded decorative palettes in consumers. Cards remain where containment has meaning; reports and metrics become open sections with hairline dividers. Do not flatten severity or running/blocked/failed state distinctions into a single accent color. Measure the actual rendered contrast and focus states rather than assume reference colors pass on every surface.
5. **Workflow pages.** Apply the system to dashboard, task workspaces, memory/curator, conversations, findings and traffic first; then agents/LLM/settings and other remaining pages. Memory stays a two-pane workspace: independently scrolling left content, viewport-persistent full-height curator on the right with bottom composer. Mobile offers explicit accessible pane switching; never simply hides the curator. Filters become a compact main toolbar plus a named advanced-filter disclosure, not a wall of unlabeled selectors. Dense results remain scrollable and details open without changing column geometry.
6. **Release verification.** Drive login/setup, navigation, memory CRUD/promotion/graduation, preview, curator source reads and approve/deny, and representative task/findings/traffic flows in the actual embedded UI. Check desktop, 390px, 320px, 200% browser zoom, keyboard focus and reduced motion; confirm existing preferences upgrade cleanly. Run applicable static/type checks and build:static, regenerate screenshots, build the embedded binary and deploy through ./lab. Graphify maps the impacted components before editing and is refreshed after integration.

## Scope boundary
This is a product/UI rebrand, not an infrastructure migration. Keep Go module paths, database/user names, ARTEX_* env variables, binary/compose identities, artex_token storage, the fixed login account, health service identifiers and published detection/guard/header wire contracts unchanged in this pass. They are compatibility/security contracts, not cosmetic labels. If technical renaming is later desired, plan explicit data/config migrations and update every detector and deployment caller as a separate approved cutover.
